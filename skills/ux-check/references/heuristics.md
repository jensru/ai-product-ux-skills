# Heuristic sets

Two sets, one per pass. One line each, written as the question to ask of the artifact. Short paraphrases for working, not quotations. For the full text read the sources linked below each set.

## ISO 9241-110:2020, interaction principles

The 2020 revision renamed and regrouped the 2006 dialogue principles. Use the 2020 names in reports, since that is the version a client or tender will look up. Older names in brackets.

| Principle | Ask |
|---|---|
| Suitability for the user's tasks (suitability for the task) | Does every step serve the task, with nothing to do that the task does not need? |
| Self-descriptiveness | Can the user tell, at every moment, where they are, what they can do and what will happen? |
| Conformity with user expectations | Does it behave the way this user group expects, from their domain, their other tools and the rest of this product? |
| Learnability (suitability for learning) | Can someone new find their way, and does the software support learning while working? |
| Controllability | Can the user start, pause, cancel, undo and set the pace, and go back without losing work? |
| Use error robustness (error tolerance) | Are errors prevented where possible, easy to fix where not, and never costly? |
| User engagement | Does it invite use, keep motivation and earn trust, without manipulation? |

Suitability for individualisation, a separate principle in 2006, is no longer one in 2020; its aspects are spread across the others.

Source: ISO 9241-110:2020, Ergonomics of human-system interaction, Part 110: Interaction principles (available from ISO and national standards bodies, not free).

## Nielsen's ten usability heuristics

| Heuristic | Ask |
|---|---|
| Visibility of system status | Does the user always know what is going on, with timely feedback? |
| Match between system and the real world | Does it use the user's words and concepts, in a natural order? |
| User control and freedom | Is there a clearly marked way out of every unwanted state, including undo? |
| Consistency and standards | Does the same thing always look, sound and behave the same, and follow platform conventions? |
| Error prevention | Does the design stop errors before they happen, instead of only reporting them? |
| Recognition rather than recall | Are options, actions and needed information visible instead of remembered? |
| Flexibility and efficiency of use | Can experienced users go faster (shortcuts, bulk actions, remembered settings) without confusing new ones? |
| Aesthetic and minimalist design | Does every element on screen earn its place, or does it compete with what matters? |
| Help users recognize, diagnose, and recover from errors | Do error messages say in plain language what went wrong and what to do? |
| Help and documentation | Where help is needed, is it findable, task-focused and short? |

Source: Jakob Nielsen, 10 Usability Heuristics for User Interface Design, Nielsen Norman Group, https://www.nngroup.com/articles/ten-usability-heuristics/

## Choosing

ISO when the result has to hold up in front of a client, an auditor or a tender, because it is a standard. Nielsen when the review is internal and fast, because everyone knows it. Both find largely the same problems; the difference is the vocabulary the report speaks.
